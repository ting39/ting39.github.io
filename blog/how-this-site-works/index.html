This site is deliberately small: plain HTML, CSS and JavaScript, served by GitHub Pages, with no framework and no build step for the homepage itself. Here is what happens behind the page you are reading.

Note

This first post was written by Claude, an AI assistant, while building the site with ting39. It's meant as documentation. ting39 can edit it, or hide it by adding draft: true to its front matter.

The homepage#

The background is a <canvas> starfield: a few hundred points drifting slowly, with faint lines drawn to your cursor when it gets close. Everything else is regular HTML. The project cards come from a single file, projects.js, so adding a project means adding one object:

Music, refreshed weekly#

The "on repeat" section lists ting39's five most-played songs of the last four weeks. A GitHub Action runs every Monday at 08:00 Taiwan time. It asks Spotify's Web API for the top tracks and commits the result to spotify.json, which the page reads. The play buttons only load Spotify's embedded player when you press one, so visitors who don't press play load nothing from Spotify.

A terminal hiding in the page#

Press ` anywhere on the site, or click the >_ in the footer. A small shell slides down. Its filesystem is built from the site's own data:

pathwhat's in it
~/projects/one file per project card
~/blog/the posts on this blog, as raw Markdown
~/music/on-repeat.txtthe same top 5 as the homepage

It has history, Tab completion, pipes (history | grep cd), man pages, and a few things help doesn't mention. The code is only downloaded the first time you open it.

This blog#

Posts are Markdown files in posts/. Pushing one triggers another Action that runs a small Node script (tools/blog/build.mjs, no dependencies) to render:

  • a page for every post, plus the index and one page per tag,
  • an Atom feed and an RSS feed,
  • posts.json, which the homepage and the terminal read.

Code blocks are highlighted at build time, so pages don't need any extra JavaScript to show colours. The output is deterministic: rebuilding without changing a post changes nothing, which keeps the commit history clean.

Why keep it this simple?#

A page that is just files keeps working with no maintenance. There are no servers, no database and no dependencies to update. When something needs to run, like the weekly Spotify refresh or rebuilding the blog, a scheduled GitHub Action does it and commits the result. Then the site is plain files again.

トップページ#

背景は <canvas> の星空です。数百個の点がゆっくり漂い、カーソルが近づくと淡い線でつながります。それ以外は普通の HTML です。作品カードは projects.js という 1 つのファイルから作られているので、作品を追加するにはオブジェクトを 1 つ足すだけです。

毎週更新される音楽#

「最近よく聴く曲」には、ting39 がこの 4 週間でよく再生した 5 曲が並びます。毎週月曜の台湾時間 08:00 に GitHub Action が動き、Spotify Web API にトップ曲を問い合わせて、結果を spotify.json にコミットします。ページはそのファイルを読み込みます。再生ボタンは押したときにだけ Spotify の埋め込みプレーヤーを読み込むので、再生しない訪問者は Spotify から何も読み込みません。

ページに隠れたターミナル#

サイトのどこでも ` を押すか、フッターの >_ をクリックすると、小さなシェルがスライドしてきます。そのファイルシステムはサイト自身のデータから作られています。

パス中身
~/projects/作品カード 1 枚につき 1 ファイル
~/blog/このブログの記事（Markdown のまま）
~/music/on-repeat.txtトップページと同じトップ 5

コマンド履歴、Tab 補完、パイプ（history | grep cd）、man ページ、そして help には載っていないものがいくつかあります。コードは初めて開いたときにだけダウンロードされます。

このブログ#

記事は posts/ に置いた Markdown ファイルです。プッシュすると別の Action が動き、小さな Node スクリプト（tools/blog/build.mjs、依存パッケージなし）で次のものを生成します。

  • 記事ごとのページ、記事一覧、タグごとのページ
  • Atom フィードと RSS フィード
  • トップページとターミナルが読み込む posts.json

コードブロックはビルド時に色付けされるので、ページ側で色を付けるための JavaScript は不要です。出力は決定的で、記事を変えずに再ビルドしても何も変わらず、コミット履歴がきれいに保たれます。

なぜこんなにシンプルなのか#

ファイルだけでできたページは、手入れをしなくても動き続けます。サーバーもデータベースも、更新が必要な依存パッケージもありません。毎週の Spotify 更新やブログの再ビルドのように何かを実行する必要があるときは、スケジュールされた GitHub Action が実行して結果をコミットします。そのあと、サイトはまたただのファイルに戻ります。

首頁#

背景是一個 <canvas> 星空：幾百個慢慢飄動的點，游標靠近時會連出淡淡的線。其他部分都是一般的 HTML。作品卡片來自單一檔案 projects.js，所以新增作品只需要加上一個物件：

每週更新的音樂#

「最近常聽」區塊列出 ting39 過去四週最常播放的五首歌。每週一台灣時間 08:00，GitHub Action 會向 Spotify Web API 查詢熱門曲目，並把結果提交到 spotify.json，頁面再讀取這個檔案。播放按鈕只有在你按下時才會載入 Spotify 的嵌入式播放器，所以沒按播放的訪客不會從 Spotify 載入任何東西。

藏在頁面裡的終端機#

在網站任何地方按 `，或點頁尾的 >_，就會滑出一個小小的 shell。它的檔案系統是用網站自己的資料建出來的：

路徑內容
~/projects/每張作品卡片一個檔案
~/blog/這個部落格的文章（原始 Markdown）
~/music/on-repeat.txt和首頁一樣的前五名

它有指令紀錄、Tab 自動完成、管線（history | grep cd）、man 說明書，還有幾個 help 沒提到的東西。程式碼只會在你第一次打開時下載。

這個部落格#

文章是放在 posts/ 裡的 Markdown 檔。推送之後會觸發另一個 Action，執行一支小小的 Node 腳本（tools/blog/build.mjs，沒有任何相依套件）來產生：

  • 每篇文章的頁面，以及文章索引和每個標籤的頁面，
  • 一個 Atom 訂閱和一個 RSS 訂閱，
  • posts.json，給首頁和終端機讀取。

程式碼區塊在建置時就上好色了，所以頁面不需要額外的 JavaScript 來顯示顏色。輸出是固定的：沒改文章就重新建置，不會有任何變化，讓提交紀錄保持乾淨。

為什麼要這麼簡單？#

一個只由檔案組成的網頁，不需要維護就能一直運作。沒有伺服器、沒有資料庫，也沒有要更新的相依套件。需要執行某些事情時，例如每週更新 Spotify 或重建部落格，就由排程的 GitHub Action 執行並提交結果。之後網站又變回單純的檔案。
