このサイトはあえて小さく作っています。素の HTML・CSS・JavaScript を GitHub Pages で配信し、
トップページ自体にはフレームワークもビルド工程もありません。いま読んでいるページの裏側で
何が起きているかを紹介します。

> [!NOTE]
> この最初の記事は、AI アシスタントの Claude が ting39 と一緒にサイトを作りながら書いたもので、
> ドキュメントとして置いています。ting39 はこれを編集したり、front matter に
> `draft: true` を足して非公開にしたりできます。

## トップページ

背景は `<canvas>` の星空です。数百個の点がゆっくり漂い、カーソルが近づくと淡い線で
つながります。それ以外は普通の HTML です。作品カードは `projects.js` という 1 つのファイルから
作られているので、作品を追加するにはオブジェクトを 1 つ足すだけです。

```js title="projects.js"
window.PROJECTS = [
  {
    title: "Gatewright",
    description: "From one NAND gate to a CPU.",
    tags: ["game", "logic"],
    link: "https://ting39.github.io/gatewright/",
  },
];
```

## 毎週更新される音楽

「最近よく聴く曲」には、ting39 がこの 4 週間でよく再生した 5 曲が並びます。
毎週月曜の台湾時間 08:00 に GitHub Action が動き、Spotify Web API にトップ曲を問い合わせて、
結果を `spotify.json` にコミットします。ページはそのファイルを読み込みます。再生ボタンは
押したときにだけ Spotify の埋め込みプレーヤーを読み込むので、再生しない訪問者は
Spotify から何も読み込みません。

## ページに隠れたターミナル

サイトのどこでも <kbd>\`</kbd> を押すか、フッターの `>_` をクリックすると、小さなシェルが
スライドしてきます。そのファイルシステムはサイト自身のデータから作られています。

| パス | 中身 |
|---|---|
| `~/projects/` | 作品カード 1 枚につき 1 ファイル |
| `~/blog/` | このブログの記事（Markdown のまま） |
| `~/music/on-repeat.txt` | トップページと同じトップ 5 |

コマンド履歴、Tab 補完、パイプ（`history | grep cd`）、`man` ページ、そして `help` には
載っていないものがいくつかあります。コードは初めて開いたときにだけダウンロードされます。

## このブログ

記事は `posts/` に置いた Markdown ファイルです。プッシュすると別の Action が動き、
小さな Node スクリプト（`tools/blog/build.mjs`、依存パッケージなし）で次のものを生成します。

- 記事ごとのページ、記事一覧、タグごとのページ
- [Atom フィード](../../feed.xml)と RSS フィード
- トップページとターミナルが読み込む `posts.json`

コードブロックはビルド時に色付けされるので、ページ側で色を付けるための JavaScript は
不要です。出力は決定的で、記事を変えずに再ビルドしても何も変わらず、コミット履歴が
きれいに保たれます。

## なぜこんなにシンプルなのか

ファイルだけでできたページは、手入れをしなくても動き続けます。サーバーもデータベースも、
更新が必要な依存パッケージもありません。毎週の Spotify 更新やブログの再ビルドのように
何かを実行する必要があるときは、スケジュールされた GitHub Action が実行して結果をコミットします。
そのあと、サイトはまたただのファイルに戻ります。
